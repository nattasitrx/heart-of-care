# Heart of Care · Pharmacist Stories

เกม Visual novel ของเภสัชกร อิงเคสผู้ป่วย Alzheimer’s และ dysphagia พร้อมฉากโรงพยาบาลอนิเมะ

- 7 ฉาก / 33 การตัดสินใจหลัก / 3 ฉากทบทวนความเสี่ยง / 4 ตอนจบ
- บทบาทเภสัชกรน้องใหม่: รับเคสจากพี่อัน ไปคุยกับทีม/ญาติ แล้วกลับมาทดสอบเหตุผลทางยา 12 ข้อ
- คำถามหลังเคส: pH/ionization, sertraline formulation, levothyroxine/interaction/TSH, modified release, ampicillin–sulbactam, ระยะยาปฏิชีวนะ, PPI, chlorhexidine, antipsychotics, ACE inhibitors และการตีความ MMSE
- ไทย, Mandarin อักษรจีนตัวเต็ม และอังกฤษ ทั้งบทสนทนา ตัวเลือก ข้ออธิบาย และหน้าสรุป
- จับเวลา 45 / 25 / 15 วินาทีต่อคำตอบในเคส; คำถามเชิงลึกให้เวลา 1.5 เท่า (68 / 38 / 23 วินาที) พร้อมหยุดพักและพักเวลาเมื่อเปิดแฟ้มเคสหรือแต่งตัว
- ความปลอดภัยรวม ความไว้วางใจและความกังวลแยกแพทย์/ผู้ดูแล/พี่เลี้ยง
- คะแนนความรู้แยกจากผลเคส: เฉลยและเหตุผลเปิดอัตโนมัติหลังตอบ มีลิงก์อ้างอิงและผลแยกตามหัวข้อ
- อารมณ์เปลี่ยนสีหน้าและบางบทสนทนา; ตอนจบขึ้นกับความปลอดภัยและความสัมพันธ์
- 2 รูปลักษณ์ × 3 ชุด ไม่มีผลต่อทักษะ; ตัวละครขนาดใหญ่ที่หน้าเริ่มเกมเปลี่ยนพร้อมภาพเล็กและห้องแต่งตัว
- คลิกคำตอบ หรือกด 1–3; Enter เพื่อไปต่อ; Escape เพื่อพัก
- ปรับขนาดตัวอักษรที่แถบด้านบนได้ 100 / 125 / 150 / 175 / 200% จำค่าต่อเบราว์เซอร์ ใช้กับบทสนทนา ตัวเลือก เฉลย แฟ้มเคสและประวัติ เปลี่ยนระหว่างเล่นได้โดยไม่เริ่มคำถามใหม่
- บันทึกประวัติกับบัญชีที่เปิดเกม ทั้งรอบที่จบและยังไม่จบ: คำถาม คำตอบที่เลือก เฉลย เวลา คะแนน สีหน้า และแหล่งอ้างอิง ส่งออก CSV สำหรับ Excel หรือ JSON ได้ทีละรอบหรือทุกรอบ
- หน้าสำหรับอาจารย์ที่ `/admin`: ดูผลรายบัญชี/รายรอบ คำตอบรายข้อ ค่าเฉลี่ยคะแนนและเวลา อัตราตอบถูก/หมดเวลา และการกระจายตัวเลือก พร้อมกรองกลุ่มเรียน วันที่ ภาษา เวลา เวอร์ชัน และรอบแรก/ล่าสุดที่จบ/ทุกรอบ
- คู่สนทนาแต่ละคนมีสีหน้าปกติ ดีใจ กังวล และประหลาดใจ เปลี่ยนทันทีตามคำตอบ; ความชอบด้านภาษา/ชุด/ชื่อเก็บเฉพาะเบราว์เซอร์

## เปิดเล่นจากไฟล์

เปิด `dist/index.html` ในเบราว์เซอร์ได้โดยไม่ติดตั้ง JavaScript เป็นแบบธรรมดาและไม่ได้ใช้ fetch โหลดเนื้อเรื่อง โหมดไฟล์ส่งออกคำตอบของรอบในหน้าที่เปิดอยู่ได้ แต่ประวัติข้ามครั้งต้องใช้เกมที่โฮสต์พร้อม backend ประวัติก่อนเพิ่มฟีเจอร์นี้ไม่มีข้อมูลให้เรียกคืน

## ประวัติบนเกมที่โฮสต์

`npm ci` แล้ว `npm run build` สร้าง Cloudflare Worker ที่ `dist/server/index.js` พร้อมหน้าเกมและรูปภาพ โดย `worker/index.js` รับ `/api/history` และบันทึกใน D1 binding `DB` ตาม schema `db/schema.ts` และ migrations ใน `drizzle/` ต้องใช้แพลตฟอร์มที่ยืนยันผู้ใช้และฉีด header `oai-authenticated-user-id` และ `oai-authenticated-user-email` จากระบบที่เชื่อถือได้ ผู้เล่นที่ลงชื่อเข้าใช้อยู่ใช้ประวัติบัญชีเดิมได้ ส่วนผู้เล่นทั่วไปใช้ cookie ที่มีลายเซ็น โดยไม่ต้องมีบัญชี ChatGPT อาจารย์ที่มีรหัสหลังบ้านอ่านผลทุกรายได้

กด “สำหรับอาจารย์” ในแถบด้านบนของเกม แล้วใส่รหัสผ่านเพื่อเปิดแดชบอร์ดในหน้าต่างเดียวกัน เกมพักเวลาระหว่างเปิดหน้าต่างนี้ ผู้ที่รู้รหัสสามารถอ่านผลผู้เล่นทุกรายได้ จึงให้รหัสเฉพาะผู้ตรวจที่ต้องเข้าถึงข้อมูล และกดออกจากระบบหลังบ้านเมื่อใช้เครื่องร่วมกัน การปิดหน้าต่างไม่ใช่การออกจากระบบ

ตั้งค่า runtime secret `ADMIN_PASSWORD_HASH` เป็น `salt:hash` รูปแบบ hex (salt 16 bytes, PBKDF2 SHA-256 100,000 iterations, hash 32 bytes) ไม่เก็บรหัสจริงในโค้ด ไฟล์ดาวน์โหลด หรือ localStorage Server ตรวจ session ทุกครั้งที่ `/admin`, `/admin.html` และ `/api/admin/sessions` สิทธิ์เดิมจากอีเมลเจ้าของไม่ใช้ข้ามรหัสผ่านอีกต่อไป Cookie เป็น HttpOnly/Secure/SameSite Strict มีอายุหนึ่งชั่วโมง เก็บเฉพาะ hash ของ session token ใน D1; logout ลบ session ที่ server จึงใช้ cookie เก่าเรียกข้อมูลไม่ได้ มีการจำกัดการลองรหัสที่ 5 ครั้งต่อ 15 นาทีต่อ IP ที่ platform ส่งให้ (hash key ไม่เก็บ IP ตรง ๆ) หากไม่มีค่า secret หรือฐานข้อมูล จะไม่เปิดหลังบ้าน

เมื่อต้องการเปลี่ยนรหัส ให้สร้าง verifier ใหม่ผ่านช่องทางที่เชื่อถือได้แล้วอัปเดต runtime secret และเผยแพร่ พร้อมล้างตาราง `admin_sessions` หากต้องการยกเลิกสิทธิ์ session เดิมทั้งหมด ผู้เล่นกรอกชื่อและรหัสนักศึกษาก่อนเล่นเพื่อบันทึกผล โดยไม่ต้องลงชื่อเข้าใช้ ChatGPT; กลุ่มเป็นช่องเพิ่มเติม รูปแบบชื่อ/กลุ่มใช้ตามคำสั่งของชั้นเรียน

## วิธีใช้สำหรับอาจารย์

ผู้เล่นไม่ต้องมีบัญชี ChatGPT แล้ว: กรอกชื่อและรหัสนักศึกษา (ต้องกรอกทั้งสองช่อง) พร้อมกลุ่มถ้ามี ระบบสร้าง cookie ผู้เล่นที่มีลายเซ็นจาก server ก่อนเริ่มเวร จากนั้นบันทึกผลใน D1 ตามเดิม ใช้ runtime secret `PARTICIPANT_SECRET` สำหรับตรวจลายเซ็น ไม่ใช้รหัสนักศึกษาเป็นรหัสผ่านสำหรับอ่านประวัติ บราวเซอร์อื่นไม่สามารถอ่านประวัติได้ด้วยการกรอกรหัสเดียวกัน ประวัติส่วนตัวจำผ่านเบราว์เซอร์เดิม; เปลี่ยนเครื่องหรือล้าง cookie จะไม่เห็นประวัติเดิม แต่ข้อมูลที่อาจารย์มีในฐานข้อมูลยังอยู่ เครื่องที่ใช้ร่วมกันควรเปิดหน้าต่างส่วนตัวและปิดเมื่อเสร็จ

สรุปรอบแรก/ล่าสุดรวมผู้เล่นตามกลุ่มและรหัสนักศึกษา (ตัดช่องว่างและไม่แยกตัวพิมพ์ใหญ่/เล็กของรหัส) เพื่อให้ผู้เรียนที่เปลี่ยนเครื่องไม่ถูกนับซ้ำ รหัสที่ไม่ระบุในข้อมูลเก่ายังรวมตามบัญชี/เบราว์เซอร์ดังเดิม ชื่อและรหัสเป็นข้อมูลที่ผู้เล่นกรอกเอง ไม่ใช่การยืนยันตัวตน

ส่งลิงก์เกมให้นักศึกษา และบอกชื่อกลุ่ม/รหัสที่จะใช้ อาจารย์กด “สำหรับอาจารย์” ใส่รหัสผ่านแล้วกดโหลดข้อมูลล่าสุด ลิงก์ `/admin` เดิมยังใช้ได้ โดยพากลับมาหน้ากรอกรหัสในเกมหากไม่มี session ระบบไม่สร้างข้อมูลนักศึกษาตัวอย่างในฐานข้อมูลจริง ค่าเริ่มต้นเลือกเฉพาะรอบล่าสุดที่จบของแต่ละกลุ่มและรหัสนักศึกษาหลังใช้ตัวกรอง หากเลือกรอบแรกจะหมายถึงรอบแรกที่จบภายในช่วงตัวกรอง; หากเลือกทุกรอบ คนที่เล่นซ้ำมีน้ำหนักมากขึ้น กรอกรหัสและกลุ่มให้ตรงกันทุกครั้ง เพื่อให้การรวมผลผู้เรียนถูกต้อง

ค่าเฉลี่ยความรู้เป็นร้อยละจากคะแนนเต็ม 12 ค่าเฉลี่ยความปลอดภัยเป็นคะแนนเต็ม 100 คิดเฉพาะรอบที่จบ; รอบที่ยังไม่จบไม่ถูกแทนเป็นศูนย์ อัตราตอบถูกรายข้อใช้เฉพาะคำตอบที่มีบันทึก รวมหมดเวลาเป็นคำตอบผิด ไม่สมมติว่าคำถามที่ยังไม่ถึงตอบผิด ทุกค่าอิงชุดข้อมูลผ่านตัวกรอง วันใช้เวลาไทเป UTC+8 คำตอบและตัวเลือกเก็บตามภาษาที่ผู้เล่นเห็น จึงแสดงการกระจายข้อความแยกภาษา

Export มี CSV สรุปคะแนน, CSV คำตอบพร้อมข้อมูลบัญชี/รหัส/กลุ่ม และ JSON พร้อมตัวกรอง สถิติ และข้อมูลเต็ม เก็บไฟล์ที่ส่งออกให้เหมาะสมกับข้อมูลผู้เรียน สำหรับการประเมินระหว่างเรียน: ชื่อ/รหัสเป็นข้อมูลกรอกเอง คะแนนยังไม่ผ่านการรับรองและระบบไม่ป้องกันการแก้คะแนนฝั่งผู้เล่น จึงไม่ใช่ข้อสอบสำหรับตัดสินผลอย่างเป็นทางการ

บันทึกเมื่อเริ่มเวร หลังคำตอบ/หมดเวลา และเมื่อจบรอบ หากบันทึกล้มเหลวเกมยังเล่นต่อได้และแสดงสถานะเตือน เปิดหน้าประวัติเพื่อลองบันทึกอีกครั้งหรือส่งออกก่อนปิดหน้า ข้อมูลที่ยังไม่ได้บันทึกจะหายเมื่อปิดหน้า ประวัติใช้สำหรับดูย้อนหลัง ไม่ใช่การกลับเข้าเล่นต่อจากจุดเดิม เปิดประวัติจะพักเวลาคำถาม CSV มี UTF-8 BOM และป้องกันการตีความข้อความเป็นสูตรสเปรดชีต JSON เก็บโครงสร้างเต็มรวมรอบที่ยังไม่มีคำตอบ

โครงสร้าง: `index.html` หน้าเกม, `styles.css` หน้าตา, `story.js` บทและคำแปลเดิม, `mentor.js` บทพี่เลี้ยงและเนื้อหาวิชาการเพิ่มเติม, `engine.js` กติกา/สถานะ, `app.js` เชื่อมส่วนติดต่อ, `assets/` ฉากและตัวละคร หากเปิดออฟไลน์ ฟอนต์สำรองของเครื่องจะใช้แทน Google Fonts

## แก้บทและกติกา

`story.js` มี helper `T(th, zh, en)` สำหรับข้อความสามภาษา โหนดมี `scene`, `npc`, `text`, `context`, `lesson`, `sources`, `options` แต่ละตัวเลือกมี `impact: { safety, trust, stress }`, `correctness` และอาจมี `flag`, `repair`, `resolves` คะแนนเป็นกลไกเกม ไม่ใช่เกณฑ์คลินิกที่ผ่านการรับรอง

`mentor.js` เพิ่มบทครอบเคสในลำดับเดิมและคำถามที่มี `academic: true`, `topic`, `timeMultiplier: 1.5` แต่ละข้อมีคำตอบถูกเพียงหนึ่งตัว (`correctness: 2`) และ `explanation` ของทุกตัวเลือก ภาษาเปลี่ยนได้โดยไม่เริ่มคำถามใหม่หรือให้คะแนนซ้ำ

คะแนนความปลอดภัยเริ่ม 50; ความไว้วางใจ/ความกังวลเริ่มตามสถานการณ์และจำกัด 0–100 ถ้าความปลอดภัยต่ำกว่า 72 หรือมีความเสี่ยงที่ยังไม่แก้ ต้องได้ตอนจบทบทวนกับทีม ความไว้วางใจสูงจึงไม่สามารถชดเชยความเสี่ยงที่ยังเปิดอยู่ การแก้ไขคำแนะนำและยืนยันแผนร่วมกับทีมสามารถปิดความเสี่ยงได้ คำตอบหมดเวลาไม่ได้อนุมัติคำแนะนำอัตโนมัติ โดยเฉพาะการส่งกลับบ้าน

ผลการดูแลเคสถูกเก็บเมื่อถึง `mentor-return` คำตอบหรือ timeout ของพี่เลี้ยงไม่เพิ่ม/ลดความปลอดภัยและไม่เปลี่ยนผลส่งต่อเคส ความรู้คิดข้อละ 1 คะแนนจาก 12 ข้อ ตอบผิด/หมดเวลาได้ 0 และยังอ่านเฉลยโดยไม่จับเวลาได้ ไม่มีเกณฑ์ผ่านรับรองสมรรถนะ

## เนื้อหาคลินิกและสิทธิ์

ข้อมูลต้นทาง: [Pharmacist Clinical Training Simulator – Dysphagia](https://pharmahht.github.io/Dysphagia2601/) โดย Huu Hiep Tran, Professor 陳崇鈺 Research Team, Kaohsiung Medical University ภายใต้ CC BY-NC-SA 4.0

นี่คือ adaptation สำหรับการศึกษาโดยไม่แสวงหากำไร คงอายุ อาการ ประวัติยา และแนวโน้มข้อมูลเคส สร้างตัวละคร บทสนทนา กลไกคะแนน เวลา รูปภาพ และตอนจบใหม่ ไม่มีข้อมูลผู้ป่วยจริงเพิ่ม

แก้จุดสอนเดิม: ไม่กำหนดน้ำผลไม้เปรี้ยวเป็นกฎสำหรับ sertraline ทุกผลิตภัณฑ์; แยกคำแนะนำยาเม็ดกับชนิดน้ำ; ตรวจรูปแบบยาที่ใช้จริงก่อนบด; ยาน้ำต้องเข้ากับแผนการกลืน; ไม่เลือกวันหยุดยาปฏิชีวนะจาก CRP ตัวเดียว; ไม่สรุปสาเหตุอาการทางสมองจากการให้ยาเพียงอย่างเดียว

รายการอ้างอิงแสดงในเกมและในแต่ละบันทึก: DailyMed, NHS SPS, BTS aspiration pneumonia 2023, NICE NG97 และงานวิจัยต้นทางเรื่อง PPI/chlorhexidine/antipsychotics/ACE inhibitors ตรวจข้อมูลวันที่ 1 ตุลาคม 2026 ดู `CONTENT_REVIEW.md` สำหรับการจับคู่หัวข้อและข้อแตกต่างจากต้นฉบับ ต้องมีผู้เชี่ยวชาญทบทวนและยืนยันแนวทาง/ผลิตภัณฑ์ท้องถิ่นก่อนใช้ประเมินผู้เรียนอย่างเป็นทางการ เกมไม่ได้เป็นคำสั่งรักษาผู้ป่วยจริง

## ตรวจสอบ

เมื่อมี Node.js: `node verify.mjs` ตรวจคำแปล โครงสร้างไฟล์ ตัวเลือกและฉากแก้ไข เวลา เงื่อนไขปลายทาง คะแนน และเส้นทางที่เกิดจากหลายตัวเลือก `node --check dist/app.js` ตรวจไวยากรณ์ของส่วนติดต่อ การทดสอบนี้ไม่ใช่การรับรองเนื้อหาคลินิก

`npm run build` แล้ว `node verify-history.mjs` ตรวจ API ด้วย SQLite จริง: แยกข้อมูลตามบัญชี การบันทึกซ้ำ/ลำดับเก่า pagination การตรวจข้อมูล และ CSV

`node verify-admin.mjs` ตรวจการจำกัดสิทธิ์อาจารย์ ตัวตนจาก server pagination หลายบัญชี สูตรคะแนน ตัวกรอง รอบแรก/ล่าสุด และการส่งออก ไม่อ่านฐานข้อมูลนักศึกษาจริงในการทดสอบ

WebMCP ถูก feature-detect โดยใช้ `document.modelContext` เมื่อเบราว์เซอร์รองรับ: read game, start shift, choose visible reply, continue, configure outfit, change language ใช้กติกาเดียวกับการกดบนหน้าจอ คำตอบจากทั้งปุ่มและเครื่องมือบันทึกผ่านระบบประวัติเดียวกัน

## ภาพ

ฉากและตัวละครเป็นงานอนิเมะใหม่จาก built-in image generation มี 1 ฉาก, 12 สีหน้าคู่สนทนา (คนละ 4 สีหน้า), 6 ตัวเลือกชุดของผู้เล่น ตัวละครเป็นผู้ใหญ่สมมติ ไม่มีความสัมพันธ์เชิงชู้สาวกับผู้ป่วย ใช้ความไว้วางใจและความร่วมมือแทนคะแนนความรัก

ดู `ASSET_PROMPTS.json` สำหรับ prompt ของภาพ และ `LICENSE.txt` สำหรับเงื่อนไขการนำไปใช้

### Game audio
Original soft instrumental loop and positive/review reply chimes are synthesized in `dist/audio.js` using Web Audio. Music and effects have independent, localized toolbar toggles, saved with browser preferences. Audio begins after the first click/tap or key press and suspends when the page is hidden. Review chime covers partially satisfactory answers, incorrect answers, and timeouts. No external audio files or service are needed. Browsers without Web Audio continue silently.
